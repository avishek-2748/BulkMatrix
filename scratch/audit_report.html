BulkMatrix
Architectural Audit & Technology Stack Rationalization Report
Architectural Review
Role: Senior Full-Stack Architect
Platform: Bulk Freight & Vessel Chartering
Focus: Overseas Origins → East Coast India

Executive Summary: BulkMatrix is an intelligent bulk cargo procurement and vessel planning platform designed to model capesize/panamax shipping dynamics to East Coast Indian ports (Paradip, Dhamra, Vizag, Haldia, Gopalpur, Gangavaram). Following an in-depth codebase audit of package manifests, Express controllers, Python forecasting engines, and Docker configs, this report establishes a lean, high-performance, non-redundant technology stack strictly adhering to the "Do Not Blindly Add" governance mandate.

D Technologies Worth Retaining & Solidifying

Docker & Docker Compose RETAINED
Justification: BulkMatrix is a polyglot architecture (Node.js + Python ML + MongoDB). Docker isolates heavy Python machine learning dependencies (CatBoost, LightGBM, Statsmodels) and enables identical local development and cloud container execution.
Scikit-learn, Pandas & CatBoost RETAINED
Justification: Actively executed inside src/prediction_pipeline.py for data normalization, route feature engineering, and evaluating multi-horizon freight rate predictions for Capesize/Panamax vessels.
Python Pickle (.pkl) RETAINED
Justification: Directly used to deserialize the 168 pre-trained per-route model artifacts stored in models/regularized/ with zero extra wrapping libraries.
GitHub Version Control & CI/CD RETAINED
Justification: The authoritative source repository triggering automated previews on Vercel and zero-downtime container deployments on Render.

E Implementation: Concrete Gaps Resolved

Auditor Fix 1: ML Dependency Reconciliation (requirement.txt)
The ML service (backend/main.py) is powered by FastAPI, but requirement.txt was missing fastapi, uvicorn, and pydantic. Any container build with Dockerfile.ml failed. Added fastapi>=0.100.0, uvicorn>=0.23.0, and pydantic>=2.0.0 to ensure reliable container compilation.
Auditor Fix 2: Production Containerization (frontend/nginx.conf, frontend/Dockerfile)
Configured a dedicated production Nginx configuration with single-page application fallback (try_files $uri $uri/ /index.html;), eliminating 404 errors on deep SPA navigation. Updated docker-compose.yml to properly map host port 5173 to container port 80.

C Technologies to Remove / Not Add (Strict Technical Rationale)

Technology Audit Verdict Architectural Rationale
Supabase DO NOT ADD Redundant. MongoDB + Mongoose is already deeply integrated with 16 active schemas. Introducing Supabase (PostgreSQL + GoTrue) forces dual databases, breaks referential integrity, and adds zero capability.
Firebase DO NOT ADD Redundant. Authentication is handled cleanly by JWT + bcrypt, and persistence is on MongoDB. Adding Firebase SDKs duplicates existing auth logic and locks the system into Google vendor constraints.
React Native DO NOT ADD Out of scope. BulkMatrix is an enterprise desktop procurement platform with wide multi-port route tables, Leaflet maps, and complex scenario planners. It is strictly a web application.
Java / Spring Boot DO NOT ADD Architectural bloat. The existing Express.js gateway and Python FastAPI service already satisfy all requirements. Adding Java introduces JVM memory overhead and fragments backend logic across 3 runtimes.
Next.js DO NOT ADD Unwarranted rewrite. BulkMatrix is an authenticated, internal procurement single-page application built on Vite. SSR/Server Components add caching complexity without providing SEO benefits behind auth.
Google Cloud (GCP) DO NOT ADD Over-engineering. Vercel (frontend) + Render (Node backend + Python ML container) + MongoDB Atlas provide automated CI/CD and cost predictability. Migrating to GCP introduces needless IAM and DevOps friction.
Framer Motion DO NOT ADD Bundle bloat. frontend/package.json already includes GSAP (gsap@3.15.0) and Tailwind CSS transitions for smooth UI animations. Adding Framer Motion adds 30KB+ of dead weight.
Redis DO NOT ADD Premature optimization. Python holds model objects in memory and MongoDB handles rate indexes. Concurrency in bulk procurement workflows does not warrant the cost and complexity of a dedicated Redis cluster.
Prisma DO NOT ADD Mismatched ORM. Mongoose is natively tailored for MongoDB schemas, discriminators, and population. Prisma is primarily designed for relational SQL and offers inferior MongoDB capability.
Botpress DO NOT ADD Mismatched function. The existing chat controller (chatController.js) handles human-to-human charter negotiations between cargo logistics managers and vessel owners. Botpress is a conversational AI bot and cannot replace contractual negotiation.
Joblib DO NOT ADD Unused. The 168 pre-trained models in models/regularized/ are serialized strictly with Python's standard pickle library. Adding Joblib adds no value.

End-to-End Operational Lifecycle:

  1. Voyage Parameter Entry: Logistics Manager inputs cargo volume (e.g., 75,000 MT coking coal), origin port (e.g., Hay Point, Australia), and target East Coast destination ports (Paradip / Dhamra).
  2. Client Dispatch: Axios dispatches an authenticated JSON payload to the Express API gateway with user JWT.
  3. Policy & Gatekeeping: Express verifies JWT claims, validates cargo tonnage, and forwards the payload to the internal ML proxy (backend/services/mlService.js).
  4. Inference Execution: FastAPI invokes charter_engine.py, extracts historical BDI lag indicators using Pandas, checks draft and beam compatibility against Indian port depth constraints, and executes the regularized CatBoost model.
  5. Output Delivery: The system computes Buy/Hold market signals, port waiting time estimates, and Capesize vs. Panamax cost trade-offs, persisting the record in MongoDB and returning high-confidence analytics to the frontend.
